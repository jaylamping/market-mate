# Ticket Creator and automatic research backlog

A dedicated Ticket Creator model proposes research tickets; research workers consume the bounded backlog as provider capacity permits. Incubator has an independent Ticket Creator model picker using the existing approved OpenRouter model catalog, a backlog target (1–100), new-ticket limit (1–100 per rolling 24 hours), unfinished-work limit (1–20), and enable/pause controls. It starts paused. Changing the creator does not change research model preferences or erase backlog entries.

The selected creator model stays fixed for each generation request. Free selections remain free; an explicit paid selection authorizes that creator for Ticket Creator, similarity, and Research Scout and reserves each cost within the recorded limits, while the general automated paid policy stays independent. Stopping an in-progress generation drops the local provider request and pauses intake; an accepted provider request may still cost money, so its unresolved receipt stays pending. There is no creator-model fallback or automatic model substitution. Campaign evaluation, refinement, and experiment calls stay on free routes even when the creator is paid. Research Scout repairs an enclosing fence or a coerced string list and allows one automatic retry after an unusable reply; archived research tickets are not picked up. Existing capacity accounting and cooldowns pace workers. Campaign claim spacing is 10 seconds so backlog pickup stays below the capacity start interval and the daily free ceiling; it is not itself an OpenRouter quota.

Ticket Creator proposes one title, economic premise and executable momentum_v1 spec per bounded call. It receives prior generated titles/specs to avoid repetition, never observed prices or account data. The backlog rejects repeated exact parameter cases deterministically; admission also uses the historical similarity check, and only the same exact momentum_v1 case counts as a duplicate. Generated output is untrusted. Database guards validate the spec and enforce the approved data contract at Setup, explicit data-request submission and dataset binding, including fallback descendants.

The initial supported research scope is the approved 20-stock universe (AAPL, MSFT, NVDA, AMZN, GOOGL, META, TSLA, AVGO, JPM, JNJ, V, UNH, PG, MA, HD, DIS, PYPL, ADBE, CRM, NFLX), SPY, zero-interest cash, and the latest 60 sessions ending before today in New York. Each admitted candidate pins exact dates. The acquisition calendar provides holidays and rejects unsupported years. These are exploratory diagnostics, not independent confirmation, statistical significance or strategy qualification. Other methods require a future supported runner.

Each worker has its own session advisory lock; row locks serialize settings and admission. Prepared generator requests survive capacity waits unchanged. A dispatched request interrupted before recording its result is never replayed. Pausing Ticket Creator fences stale generated output from entering the backlog; existing backlog cards still receive a similarity check and research admission on the selected creator. Incomplete similarity checks record the original result, queue a linked retry, and leave the campaign running. Exact-case duplicates leave the live queue. Uncertain provider outcomes still block another dispatch. Audit events preserve configuration, creator request/result, candidate claim and admission outcomes. Mutable control tables retain queue state; runtime roles have no direct table-write privileges.

The campaign runs continuously; ten completed experiments is an acceptance milestone, not a shutdown condition. Defaults for new configurations are 50 daily tickets, a 100-ticket backlog and ten unfinished tickets. The latest 100 candidate entries are displayed and included in creator context; exact-spec deduplication still checks all history. Completion counts are derived independently from experiment completion records. Admission, report generation, evaluator rejection and experiment failure do not count as completed experiments. The creator is capped at 500 generation jobs per rolling 24 hours and pauses on an uncertain outcome or three consecutive failures.

`bash scripts/research_campaign_test.sh` uses a disposable database and model-output doubles to probe backlog ingestion, capacity-independent storage boundaries, pause, pacing, settings revisions, restart identity, duplicate checks, scope enforcement, role restrictions, and continuous intake beyond 25 admissions and the daily cap. The live pass condition remains ten model-created tickets reaching completed experiments with observed data. Synthetic probe outcomes never count toward that live result.

Ticket Creator usage is shown separately for the last 24 hours and lifetime, with the latest 20 dispatched calls. Costs use the capacity receipt ledger, including failed calls; unresolved costs remain pending. Input/output tokens use provider usage reports. Reasoning tokens are a reported subset of output tokens, never added twice.
