# Ticket Creator and automatic research backlog

A dedicated Ticket Creator model proposes research tickets; free research workers consume the bounded backlog as provider capacity permits. Incubator has an independent Ticket Creator model picker using the existing approved OpenRouter model catalog, a backlog target (1–20), new-ticket limit (1–10 per rolling 24 hours), unfinished-work limit (1–3), and enable/pause controls. It starts paused. Changing the creator does not change research model preferences or erase backlog entries.

The selected creator model stays fixed for each generation request. Free selections remain free; a paid selection requires the existing automated spending policy to explicitly allow that model and reserve its cost. There is no creator-model fallback or automatic model substitution. Campaign research, similarity, evaluation, refinement and experiment calls stay on free routes even when other automated paid work is enabled. Existing capacity accounting and cooldowns pace both workers.

Ticket Creator proposes one title, economic premise and executable momentum_v1 spec per bounded call. It receives prior generated titles/specs to avoid repetition, never observed prices or account data. The backlog rejects repeated exact parameter cases deterministically; admission also uses the existing complete historical similarity check. Generated output is untrusted. Database guards validate the spec and enforce the approved data contract at Setup, explicit data-request submission and dataset binding, including fallback descendants.

The initial supported research scope is the approved 20-stock universe (AAPL, MSFT, NVDA, AMZN, GOOGL, META, TSLA, AVGO, JPM, JNJ, V, UNH, PG, MA, HD, DIS, PYPL, ADBE, CRM, NFLX), SPY, zero-interest cash, and the latest 60 sessions ending before today in New York. Each admitted candidate pins exact dates. The acquisition calendar provides holidays and rejects unsupported years. These are exploratory diagnostics, not independent confirmation, statistical significance or strategy qualification. Other methods require a future supported runner.

Each worker has its own session advisory lock; row locks serialize settings and admission. Prepared generator requests survive capacity waits unchanged. A dispatched request interrupted before recording its result is never replayed. Pausing or changing the creator fences stale output from entering the backlog. Incomplete similarity checks pause new admission. Already-admitted research continues. Audit events preserve configuration, creator request/result, candidate claim and admission outcomes. Mutable control tables retain queue state; runtime roles have no direct table-write privileges.

The current acceptance campaign stops admission at ten research tickets and preserves unused backlog entries. Completion counts are derived independently from experiment completion records. Admission, report generation, evaluator rejection and experiment failure do not count as completed experiments. The creator is capped at 40 generation jobs per rolling 24 hours and pauses on an uncertain outcome or three consecutive failures.

`bash scripts/research_campaign_test.sh` uses a disposable database and model-output doubles to probe backlog ingestion, capacity-independent storage boundaries, pause, pacing, settings revisions, restart identity, duplicate checks, scope enforcement, role restrictions, and the ten-ticket cap. The live pass condition remains ten model-created tickets reaching completed experiments with observed data. Synthetic probe outcomes never count toward that live result.
