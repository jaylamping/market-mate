# Automatic research campaign

The first campaign is a bounded momentum sensitivity agenda targeting ten automatically admitted research tickets. It starts paused; the owner can enable it in Incubator, set 1–10 candidate checks per rolling 24 hours, and cap unfinished campaign tickets at 1–3. Candidates are separated by at least 60 seconds. A finite set of 33 predefined cases supplies alternatives when historical research overlaps. These are exploratory cases, not independent confirmation or selection of a winning strategy.

Research Scout writes the actual research reports. The scheduler supplies each explicit hypothesis, runner parameters and data scope, checks it against assignment history through the existing similarity checker, then admits it through the existing research assignment function with automatic provenance. It does not use the manual paid-admission path. The approved free Research model is the initial route; the saved automated capacity/spending policy still governs permitted fallback and every downstream model call.

The scope is the approved 20-stock universe (AAPL, MSFT, NVDA, AMZN, GOOGL, META, TSLA, AVGO, JPM, JNJ, V, UNH, PG, MA, HD, DIS, PYPL, ADBE, CRM, NFLX), SPY, zero-interest cash, and the latest 60 sessions ending before today in New York. Each candidate pins exact dates before any model call. The existing acquisition calendar supplies holidays and rejects unsupported years. This agenda requires no graph functionality or new market data vendor.

The worker runs within incubator-requests. Its session advisory lock prevents simultaneous workers from processing a candidate, and database row locks serialize claims, settings changes and admission. A restart reads the same recorded check and never replays an uncertain comparison. An incomplete check pauses the campaign; duplicates consume a candidate but create no ticket. A changed history digest blocks admission. A settings revision or pause during checking fences admission; already-admitted tickets continue. Configuration, candidate claims, and outcomes have audit events; mutable control tables retain the queue and state. No direct table writes are granted to the runner.

Ten queued research tickets stops new admission. Completed counts are independently derived from stored experiment completion records. The UI does not equate admission, a generated report, an evaluator closing an idea, or a failed experiment with completion. Existing evaluation, refinement, data acquisition and deterministic execution retain their current bounded guards. Blocked or failed work remains visible for diagnosis.

Run `bash scripts/research_campaign_test.sh` for isolated mechanism checks. It verifies pause, pacing, limits, restart identity, duplicate rejection, immutable admission identity, stale settings, existing worker pickup, restricted roles, audit integrity, and the ten-ticket cap. Its synthetic terminal outcomes test admission only; they do not count as the live acceptance run. The live pass condition is ten automatically created campaign research tickets with stored completed observed-data experiment results.
