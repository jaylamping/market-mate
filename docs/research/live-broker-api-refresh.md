# Live broker/API refresh

Research date: 2026-08-16
Scope: U.S. individual account owned by a Kansas resident; cloud-hosted stock and listed-options automation; approximately $1,000 initial trading capital; defined-risk, atomic multi-leg orders; paper validation may use a different venue.

## Principal decision overlay

After reviewing this research, the Principal selected **Tradier, Alpaca, tastytrade, Interactive Brokers (IBKR), and Schwab/thinkorswim** for the initial comparative certification program. Tradier and Alpaca are the current front-runners, but all five receive the same hard-gate, scorecard, usability, and cost evaluation. Only a qualified winner may receive the initial live allocation. A venue's unsupported paper API or interactive authentication is recorded as failed or unavailable evidence for the affected capability rather than silently assumed. This decision changes the certification sequence, not the primary-source facts below.

## Decision summary

No candidate is certified for live use from documentation alone. The current shortlist is:

1. **Tradier as the primary cloud-first certification candidate.** Its individual API token does not expire, its sandbox implements the trading API, it documents atomic 2–4-leg option orders, order preview with buying-power validation, live account/order streams, SPX-family option roots, and explicit rate limits. The major unanswered questions are box-spread acceptance and collateral treatment, API-visible exercise/assignment lifecycle, token privilege restriction, and operational guarantees.
2. **Interactive Brokers (IBKR) as the box-spread/product-breadth certification candidate.** IBKR explicitly lists Long Box Spread in its options permission levels and documents combination orders, paper trading, WhatIf previews, WebSocket events, SPX instruments, and broad options support. However, the individual Client Portal Web API cannot automate authentication, requires browser reauthentication at least daily, and is documented as a local-machine gateway. This conflicts with unattended cloud operation unless IBKR gives written approval for a different supported individual authentication path (or the project accepts a daily human session ceremony). The TWS/IB Gateway API could be evaluated separately, but must not be assumed to solve authentication without a live proof.
3. **tastytrade as an options-centric alternate.** It provides sandbox access, session/remember tokens, trade-only account authority in its data model, complex-order and dry-run endpoints, account streaming, margin dry-runs, transactions, and low options commissions. Its public docs do not prove the exact four-leg box/SPX/XSP acceptance, credential lifecycle for durable unattended production, rate limits, or API controls for exercise/do-not-exercise.
4. **Alpaca as the best developer ergonomics/paper alternate, conditional on product certification.** It has separate paper/live endpoints, static API-key authentication suitable for services, live atomic multi-leg orders, order WebSockets, and detailed financial activity events. Public docs are not sufficiently clear that an individual Trading API account can trade SPX/XSP boxes; basic options data is indicative rather than full OPRA. A live account must also qualify for Level 3.
5. **Schwab is not presently certifiable from accessible primary API documentation.** Schwab publicly advertises stocks/options, $0.65 option contracts, and thinkorswim paperMoney, but the public evidence reviewed here does not establish that paperMoney is an API sandbox, that the Individual Trader API supports durable unattended OAuth, or that it atomically accepts four-leg boxes. Keep it out of the first proof-of-concept unless Schwab supplies current written/API documentation covering those requirements.

The recommended architecture remains broker-neutral: implement a venue adapter contract, evaluate Tradier and Alpaca first as the Principal's current front-runners, retain IBKR as the specialized box-spread/product-breadth candidate, and allow the paper venue to differ from live. All five candidates receive the same hard gates and weighted evaluation with no scoring preference. Do not choose a live broker until the broker passes the executable certification suite described below.

## Primary-source findings by venue

### Tradier

- Tradier documents individual API tokens as non-expiring and explicitly says individual developers do not need OAuth. Partner OAuth supports `read`, `write`, `market`, `trade`, and `stream` scopes; refresh tokens are partner-only. This is the best documented fit for a continuously running personal cloud service, but a static personal token appears to be a bearer secret with broad account access and must be protected accordingly. [Tradier authentication](https://docs.tradier.com/docs/authentication), [Tradier FAQ](https://docs.tradier.com/docs/faq)
- Sandbox and production use separate URLs and tokens. The sandbox implements paper trades and the trading API, but its data is delayed by 15 minutes; therefore it can validate lifecycle logic but cannot by itself validate fill realism or an earnings strategy. [Tradier endpoints](https://docs.tradier.com/docs/endpoints), [Tradier FAQ](https://docs.tradier.com/docs/faq)
- Tradier explicitly documents pure-options multi-leg orders with up to four indexed legs and debit/credit/even pricing. It also exposes `preview=true`; all validation rules, including buying power, run during preview, and the response can contain fees, commission, cost, and margin change. [Tradier trading guide](https://docs.tradier.com/docs/trading)
- Account streaming sends order status transitions and heartbeats; REST order objects expose order ID, open/partial/filled/rejected states, execution quantities, fill prices, remaining quantity, rejection reason, and tags. [Tradier account streaming](https://docs.tradier.com/docs/account-streaming-responses), [Tradier order model](https://docs.tradier.com/docs/orders)
- Options-symbol lookup explicitly includes additional roots such as SPXW and RUTW, and the fee schedule lists SPX and XSP exchange fees. This proves index-option awareness, not that a four-leg box will be approved in this specific $1,000 account. [Tradier option-symbol lookup](https://docs.tradier.com/reference/brokerage-api-markets-get-lookup-options-symbols), [Tradier pricing](https://production.tradier.com/individuals/pricing)
- Tradier publishes 60/min production trading, 120/min production account/market, and 60/min sandbox limits per token. Market/account streaming is preferable to polling, but only one stream of each type is permitted and an account stream is live or sandbox, not both. [Tradier rate limits](https://docs.tradier.com/docs/rate-limiting), [Tradier streaming](https://docs.tradier.com/docs/streaming-data)

### Interactive Brokers

- The Client Portal Gateway is a serious constraint: IBKR says individual clients cannot automate its authentication, must reauthenticate in a browser at least once after midnight each day, and should run the gateway locally. The design cannot label IBKR Client Portal API “fully autonomous” while that condition remains. [IBKR Client Portal Web API](https://ibkrcampus.com/campus/ibkr-api-page/cpapi-v1/)
- IBKR documents paper usernames/accounts and recommends paper testing. A live account must be fully open and funded even to use its associated simulated account. [IBKR Web API access](https://ibkrcampus.com/campus/ibkr-api-page/web-api-trading/)
- The Client Portal API supports combination/spread payloads (`conidex`) and WhatIf order preview; WebSocket communications and account/order/trade endpoints are documented. The exchange determines allowable leg count. [IBKR Client Portal Web API](https://ibkrcampus.com/campus/ibkr-api-page/cpapi-v1/)
- IBKR explicitly lists Long Box Spread under Level 2 options permissions. Its TWS documentation names a Box strategy and gives the expected four-leg construction. This is the strongest product-level evidence in the candidate set, but it does not prove that a $1,000 account will receive the needed permissions or collateral treatment. [IBKR options permission levels](https://www.ibkrguides.com/clientportal/optionstradingpermissions.htm), [IBKR combination orders](https://www.ibkrguides.com/traderworkstation/about-combination-orders.htm)
- “Atomic” needs precise certification. IBKR states that a combo routed directly to an exchange executes as a single transaction, while a SmartRouted combination can execute legs separately. The adapter must require guaranteed/exchange-native routing or explicitly model legging risk; merely sending a combo object is insufficient. [IBKR combination orders](https://www.ibkrguides.com/traderworkstation/about-combination-orders.htm)
- Web API has a global 10 requests/sec limit, endpoint-specific limits, nightly brokerage resets near 01:00 local region time, and Saturday maintenance. [IBKR Web API operations](https://ibkrcampus.com/campus/ibkr-api-page/webapi-doc/)
- IBKR advertises no standard account minimum and publishes tiered/fixed options commissions, but market-data entitlements and user-specific subscriptions can add cost. Use live statements and the official pricing calculator during certification rather than hard-coding a headline rate. [IBKR options commissions](https://www.interactivebrokers.com/en/pricing/commissions-options.php)

### tastytrade

- tastytrade documents session login and an optional remember token, plus a certification sandbox. Public documentation reviewed does not provide enough lifecycle detail to conclude that a remember token enables indefinitely unattended live operation; obtain written production behavior and prove renewal/revocation. [tastytrade basic API usage](https://developer.tastytrade.com/basic-api-usage/), [tastytrade API FAQ](https://developer.tastytrade.com/faq/)
- Account data includes authority levels of owner, trade-only, and read-only. Trade-only is directionally ideal because it cannot deposit/withdraw, but the project must confirm that a personal owner can provision a separate API user with trade-only authority. [tastytrade basic API usage](https://developer.tastytrade.com/basic-api-usage/)
- The API exposes create/get/update/cancel for complex orders plus dry-run endpoints, a margin dry-run, live orders, account streaming, transactions, balances, and positions. These are strong primitives for preview and reconciliation. [tastytrade orders API](https://developer.tastytrade.com/open-api-spec/orders/), [tastytrade margin requirements API](https://developer.tastytrade.com/open-api-spec/margin-requirements/)
- Pricing is $1 per stock/ETF option contract to open (up to $10 per leg) and $0 to close; broad-based index options are $1 open and $0 close, with other fees. That pricing matters on a $1,000 account and must be included in box yield calculations. [tastytrade options pricing](https://tastytrade.com/options)
- First-party materials describe automatic exercise of equity/ETF options at $0.01 ITM and assignment/pin risk. The API timing and content for those events, and an API-accessible DNE action, require proof. [tastytrade options lifecycle](https://tastytrade.com/learn/trading-products/options/what-are-options/)

### Alpaca

- Paper and live endpoints use API key/secret authentication and separate WebSockets. Alpaca documents paper options enabled by default and live Level 3 multi-leg support. [Alpaca options trading](https://docs.alpaca.markets/us/docs/options-trading), [Alpaca Level 3](https://docs.alpaca.markets/us/docs/options-level-3-trading)
- Four-leg MLeg orders are explicitly described as filling together or not at all. Orders contain broker and client IDs; WebSockets emit fills, partial fills, cancels, and rejects. Account Activity and Trade Events provide complementary financial and order-lifecycle streams, including per-leg events for MLeg orders. [Alpaca Level 3](https://docs.alpaca.markets/us/docs/options-level-3-trading), [Alpaca WebSocket trading](https://docs.alpaca.markets/us/docs/websocket-streaming), [Alpaca activity events](https://docs.alpaca.markets/us/docs/activity-sse)
- Options material documents Level 1–3, exercise and DNE APIs, and options activities. Broker API marketing additionally claims automated exercise/assignment event transmission. These should be replay-tested; Broker API partner capabilities must not be assumed to exist identically in a personal Trading API account. [Alpaca options overview](https://docs.alpaca.markets/us/docs/options-trading-overview), [Alpaca Broker API](https://alpaca.markets/broker)
- Basic data supplies only IEX equity coverage and an indicative options feed. The current Algo Trader Plus plan is $99/month for complete stock/options coverage, which is an operating cost separate from the $1,000 but is still economically material. [Alpaca market-data plans](https://docs.alpaca.markets/us/docs/about-market-data-api), [Alpaca data pricing](https://alpaca.markets/data)

[Alpaca API commissions](https://alpaca.markets/partnerships), [Alpaca regulatory fees](https://docs.alpaca.markets/us/docs/regulatory-fees)

### Schwab

- Schwab publicly advertises thinkorswim paperMoney, $0 online listed stock/ETF commissions, and $0.65 per listed-options contract. This does not establish API paper support or complex-order behavior. [Schwab trading](https://www.schwab.com/trading), [Schwab trading support](https://www.schwab.com/trading/support)

## Box-spread cautions specific to this experiment

“Supports four legs” is not the same as “supports a box spread.” Certification must independently prove:

- the exact SPX/XSP (European-style, cash-settled) contracts available to this individual account;
- both opening and closing four-leg limit orders are accepted as one strategy and how they route;
- long versus short box permissions (these are economically lending versus borrowing and may have different approvals/margin treatment);
- buying-power/collateral result before and after fills, including early exercise/assignment exposure if American-style equity/ETF options are used;
- contract multiplier, expiration settlement, exercise cutoffs, pin/settlement risk, and broker liquidation policy;
- all commissions, exchange, clearing, regulatory, exercise/assignment, and subscription costs; and
- minimum price increments and realistic fills. A riskless terminal payoff does not guarantee a profitable entry after costs or execution.

For this plan, **SPX/XSP box support remains uncertified at every venue**. IBKR has explicit product/permission evidence, Tradier has explicit SPX-family symbols and four-leg mechanics, tastytrade has broad-index pricing and complex orders, and Alpaca has MLeg mechanics; none of those facts alone proves the full end-to-end strategy for this account.

## Executable broker certification path

Use a dedicated adapter test account and preserve all requests/responses, timestamps, venue IDs, statements, and screenshots as certification evidence.

### Gate 1 — written broker answers before funding

Ask each shortlisted broker to answer in writing:

1. May a Kansas-resident personal account with approximately $1,000 obtain the options level needed for defined-risk four-leg spreads?
2. Are SPX and XSP available through the named individual API, and are long boxes and short boxes permitted? What minimum equity, margin account, or collateral rules apply?
3. Does a four-leg box route as a guaranteed/atomic complex order? Can any legs fill separately under smart routing, cancellation, replacement, or partial fill?
4. What authentication method is supported for an unattended cloud service? What human reauthorization, 2FA, session reset, IP, or gateway requirements apply?
5. Can credentials be restricted to read + trade with all withdrawals/transfers disabled? How are they revoked and rotated?
6. Which API events/report records represent exercise, assignment, expiration, cash settlement, trade corrections/busts, fees, and forced liquidation, and when are they delivered?
7. What paper-versus-live differences exist for option approvals, buying power, fills, exercise/assignment, market data, and outage behavior?
8. What rate limits, planned maintenance, status/incident feeds, and support escalation channels apply?

### Gate 2 — sandbox contract tests

- Authenticate from the intended cloud runtime and survive token/session rotation and scheduled resets.
- Discover contracts by stable instrument identity; verify multiplier, exercise style, settlement style, expiration, and last-trade timestamps.
- Preview and submit 2-, 3-, and 4-leg limit orders; prove all-or-none strategy behavior, cancel/replace, reject, timeout, duplicate/idempotency, and partial-fill semantics.
- Capture client ID, broker order ID, leg IDs, execution IDs, every state transition, fees, margin/buying-power change, and rejection details.
- Reconcile REST snapshots against streaming events after intentional disconnect/replay.
- Simulate expiration, early assignment, exercise, DNE, corporate action, stale quote, halted instrument, and venue outage. Where sandbox cannot simulate one, require a broker-provided test or mark it unproven.
- Run paper with the exact live Risk Policy. Delayed or unrealistic paper fills cannot certify strategy profitability.

### Gate 3 — live minimum-size certification

After paper validation and human approval, use the smallest broker-permitted defined-risk positions. Start with stock/long option or a simple vertical before any box. Require:

- preview values match accepted order and resulting account state within documented tolerances;
- complex order routing/fills match the atomicity contract;
- every cent reconciles among events, transaction history, confirmations, and statements;
- options lifecycle events arrive early enough for the Options Lifecycle Engine;
- credential revocation, kill switch, cancel-all, fail-closed recovery, and alert escalation work; and
- paper/live slippage, fees, margin, and rejection differences are measured and displayed.

Only after the broker passes those tests should a specific adapter/version be labeled **Certified Live Venue**. Certification expires on a material API, fee, authentication, routing, margin, product, or lifecycle change.

## Recommendation for the decision ticket

Adopt a **five-candidate, evidence-gated certification path** rather than selecting a broker now. Begin evidence collection with the Principal's current Tradier and Alpaca front-runners, without giving either a scoring preference:

- Certify **Tradier first** for cloud operation, preview/reconciliation, and 2–4-leg mechanics.
- Certify **Alpaca** in parallel for cloud authentication, event completeness, individual-account options products, and full-data economics.
- Seek **IBKR written confirmation** for an individual supported authentication mode compatible with cloud operation and prove box routing/permissions. If daily human authentication remains required, IBKR can still be a human-supervised venue but cannot satisfy the eventual unattended-live destination.
- Keep **tastytrade** as the fallback if it confirms durable authentication, a provisionable trade-only user, four-leg index boxes, and complete lifecycle events.
- Defer **Schwab** until primary documentation or approved-app testing closes its API/auth/paper/complex-order unknowns.

This research makes no claim that any broker will approve this account for options or that box spreads will produce a positive return. Approval is individualized, broker rules change, and the $1,000 bankroll may make available boxes economically or operationally unsuitable.
