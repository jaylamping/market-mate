# Local market data setup and refresh

WU-63 adds **System → Market data**, a private connector service and experiment collection controls. It extends the [acquisition worker](automatic-market-data-acquisition.md) and [storage policy](market-data-storage.md).

Enter Alpaca API credentials and confirm that the account terms permit retaining historical data for personal research. The connector checks a small January 2026 adjusted daily SIP panel before saving credentials in a private, mode-0600 file in the `market-data-secrets` Docker volume. Setup does not accept provider terms, buy access, upgrade an account or place orders. The source registry records an owner account review, not independent provider certification. API keys stay out of database evidence, model prompts and status responses. The internal service has no published port; the frontend forwards bounded, local same-origin setup requests.

An awaiting experiment with a valid Setup request collects automatically. Older tickets can specify symbols, dates and a benchmark once in the experiment panel. The supported NYSE calendar is explicitly pinned to 2025–2026; dates outside it fail validation. Calendar expansion requires a versioned update before 2027. The diagnostic permits at most 60 sessions. The UI shows request assumptions, collection state, error, Retry and Cancel. Existing dataset attachment remains available under Advanced.

Collection starts enabled after successful setup. Refresh is opt-in. After 6 a.m. New York time on a supported trading day, refresh queues a rolling window ending with the previous completed session for each active completed automatic acquisition. It catches up the current window after downtime, retains the requested universe and never rebinds the experiment. Archived or superseded research cannot complete refresh. Leases recover after five minutes, at most three claims; a failed download is shown in status and the following scheduled session can try again. Pause fences database attachment; a bounded request already in flight can finish without storing its response.

Once per UTC day, housekeeping invokes the existing 90-day unused-panel cleanup, including while collection is paused. Referenced experiments retain replay inputs. This is active-store cleanup: Docker volume backups need their own deletion policy. Credentials persist until replaced or their private volume is explicitly removed. No provider response body is written to application logs.

Validation: `bash scripts/wu63_market_data_test.sh` creates and destroys its own database, uses a loopback provider double, and verifies setup, role restrictions, attachment, calendar timing, refresh deduplication, pinned inputs, pause/archive fences and daily housekeeping. Frontend tests exercise the same-origin proxy and bounded secret payload. Desktop and 390px setup layout were inspected. A separately authorized live smoke test passed using the existing Alpaca connection: AAPL, XOM, JPM, NEE and SPY over January 5–8, 2026 (20 observations). Its metadata-only receipt is `evidence/wu-63/live-smoke.json`; the panel remains private and unregistered. Mock acceptance remains marked `live_provider_tested: false`. Technical API access does not record an account-terms acknowledgement or enable persistent collection.

Provider reference: [Alpaca market data FAQ](https://docs.alpaca.markets/us/docs/market-data-faq) and [historical stock bars](https://docs.alpaca.markets/us/reference/stockbars). Account-specific access is checked at setup; personal/noncommercial use alone is not recorded as evidence of data rights.
